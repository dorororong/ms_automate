# 학교 업무 메시지 → Outlook 일정·할 일

학교에서 오는 공지·메일·메신저 메시지를 읽고, 거기 들어 있는 **일정과 할 일을 뽑아
클래식 Outlook에 등록**하는 Windows 데스크톱 앱입니다.

메시지를 복사해 단축키 한 번을 누르면, 배경에서 Solar Pro 4가 내용을 분석하고,
기존 Outlook 내역과 겹치는 것을 걸러낸 뒤, 카드 하나하나를 눈으로 확인하고
`등록`을 눌러 끝냅니다.

```text
텍스트 선택(Ctrl+Shift+X) · 붙여넣기(Ctrl+V) · 파일 드롭
        ↓
FIFO 분석 대기열 (백그라운드)
        ↓
Solar Pro 4 구조화 JSON 분석  ─ 키 없거나 실패하면 → 오프라인 규칙 분석
        ↓
SQLite에 pending 기록
        ↓
로컬 Outlook 미러로 시간 겹침 · 중복 제외
        ↓
검토창: 왼쪽 원문 / 오른쪽 카드
  카드마다 [등록] [미등록] — 한 건씩 그 자리에서 처리
  분석이 끝난 다음 메시지는 같은 창에 이어 붙음
        ↓
클래식 Outlook Calendar / Task 생성 (COM)
  마감이 있는 작업은 마감일에 종일 표시도 함께
        ↓
SQLite에 saved + EntryID 기록
```

**메일을 보내지 않고 Microsoft Graph도 호출하지 않습니다.** Outlook은 이 PC의
로컬 COM으로만 조작합니다. 학교 네트워크가 외부 API를 막아도 등록 흐름은 돕니다.

- 저장소: [dorororong/ms_automate](https://github.com/dorororong/ms_automate) (비공개)
- 참고한 원본: [progh2/catmoa](https://github.com/progh2/catmoa)
- 구현 근거와 평가 기록: [IMPLEMENTATION_REPORT.md](IMPLEMENTATION_REPORT.md)
- 프롬프트 축소와 속도 실측: [LATENCY_REPORT.md](LATENCY_REPORT.md)
- 행동 단위 추출 규칙: [ACTION_EXTRACTION_SPEC.md](ACTION_EXTRACTION_SPEC.md)
- 진행 상태와 다음 작업: [WORK_TREE.md](WORK_TREE.md)

## 배경

이 앱은 **[CATMOA](https://github.com/progh2/catmoa)** 에서 출발했습니다.
교사 개발자 해커톤 결과물이고 저도 공동 참여했습니다. 메시지를 넣으면 일정을 뽑아
캘린더에 넣어 주는 흐름과, 화면 구석의 작은 입력 창이라는 형태를 여기서 가져왔습니다.

다시 만든 이유는 **학교 환경에서 Google API를 다루는 데 제한이 있기 때문**입니다.
학교 서버·네트워크에서 막히면 캘린더 등록이 통째로 멈춥니다. 그래서 일정을 Python
명령으로 직접 다룰 수 있는 **Outlook 버전으로 다시 개발**했습니다. Outlook은 이 PC의
로컬 COM으로 조작하므로 외부 API 차단과 분리되어 동작합니다.

여기에 두 가지를 더했습니다.

- **UI를 더 단순하게.** 작은 창에서 입력란과 실행 버튼을 걷어내고 상태만 남겼고,
  검토창은 카드에서 바로 `등록`/`미등록`을 눌러 끝내도록 정리했습니다.
- **교사가 무료로 쓸 수 있는 [Upstage Solar Pro 4](https://console.upstage.ai/)**
  로 분석을 붙이고 테스트했습니다. API 키가 없어도 오프라인 규칙 분석으로 돕니다.

원본 CATMOA 저장소에는 아무 변경도 가하지 않았습니다.

## 빠른 시작

### 실행 환경

| 항목 | 요구사항 |
|---|---|
| OS | Windows 10 / 11 |
| Python | 3.11 이상 |
| Outlook | **클래식** 데스크톱 앱, 로그인된 상태 (New Outlook 단독 환경은 불가) |
| Upstage API 키 | 선택. 없으면 오프라인 규칙 분석만 사용 |

### 설치

```powershell
python -m pip install -r requirements.txt
```

주요 의존성은 `pywin32`(Outlook COM·단축키·트레이), `openai`(Upstage 호환 클라이언트),
`Pillow`(아이콘·이미지), `pdfplumber`·`olefile`(문서 추출), `tkinterdnd2`(드래그앤드롭),
`pytesseract`(이미지 OCR, 선택)입니다.

### API 키

프로젝트 루트에 `.env`를 만들거나 환경변수로 넣습니다.

```text
UPSTAGE_API=up_...
UPSTAGE_MODEL=solar-pro4
```

```powershell
$env:UPSTAGE_API = "up_..."
```

`UPSTAGE_API_KEY`, `SOLAR_API_KEY`라는 이름도 인식하며 우선순위는
`UPSTAGE_API` → `UPSTAGE_API_KEY` → `SOLAR_API_KEY`입니다.
`.env`는 로컬 전용이며 Git에 커밋하지 않습니다.

### 사용자 프로필

`담임`인지 `업무`인지 판정하려면 사용자가 누구인지 알아야 합니다.
`profile.example.json`을 복사해 `profile.json`을 만들고 채우세요. (Git 제외)

```json
{
  "role": "예: 중학교 교사",
  "department": "",
  "subject": "",
  "notes": ""
}
```

### 실행

```powershell
python app.py
```

작업 표시줄 바로 위 오른쪽에 작은 상태 창이 붙어서 뜨고, 알림 영역에 아이콘이 생깁니다.

### 첫 사용 흐름

1. 다른 앱에서 업무 메시지를 마우스로 선택합니다.
2. **Ctrl+Shift+X**를 누릅니다. 작은 창이 `처리 중`으로 바뀝니다.
3. 분석이 끝나면 검토창이 열립니다.
4. 카드의 제목·날짜를 확인하고 `등록` 또는 `미등록`을 누릅니다.
5. 남은 카드와 분석이 모두 없어지면 창이 저절로 닫힙니다.

## 화면

### 작은 상태 창

`180×128`. 작업 표시줄 바로 위 오른쪽 끝에 붙습니다. 다른 창을 가리지 않도록 작게
두었고, **입력창도 실행 버튼도 없습니다.** 지금 무슨 일이 일어나는지만 보여줍니다.
켜져 있는 동안 항상 화면 위에 남습니다.

제목 표시줄이 없어 최소화·닫기 버튼도 없습니다. 창을 옮기려면 위쪽 `업무 정리`
줄을 잡고 끌면 됩니다. 숨기기와 종료는 트레이 아이콘에서 합니다.
(트레이 아이콘을 만들지 못한 환경에서는 제목 표시줄이 그대로 남아 창으로 끌 수
있습니다.)

| 상태 | 뜻 |
|---|---|
| `대기 중` | 지금 넣으면 됩니다 |
| `처리 중 n건` | Solar Pro 4가 분석하는 중 |
| `대기 n건` | 분석이 끝났고 검토창을 여는 중 |
| `검토 중` | 검토창이 열려 있음 (분석이 남아 있으면 `분석 n`도 함께) |
| `일시중지` | 새 입력을 받지 않는 상태 |

창이 작아 짧은 말만 들어갑니다. 같은 내용을 풀어 쓴 문장과 Outlook 동기화 상태는
`⋯` 메뉴 맨 위에 있습니다.

- 창을 클릭 → 파일 선택 창
- 창에 파일을 드롭 → 바로 읽기
- `⋯` 메뉴 → 선택 텍스트 가져오기 · 붙여넣기 · 파일 선택 · 일시중지 ·
  Outlook 연결 확인 · 단축키 안내 · 종료

### 트레이 아이콘

알림 영역 아이콘을 오른쪽 클릭하면 `창 보이기` · `일시중지`/`재개` · `종료`가 나옵니다.
왼쪽 클릭하면 창이 앞으로 나옵니다.

작은 창에는 최소화·닫기 버튼이 없으므로 **숨기기와 종료는 트레이에서** 합니다.
`⋯` 메뉴에도 같은 항목이 있습니다. 트레이 아이콘을 만들지 못한 환경에서는 작은 창이
제목 표시줄을 그대로 유지하고 `X`가 앱을 종료합니다.

일시중지 중에는 단축키·드롭·붙여넣기로 들어온 입력을 대기열에 넣지 않습니다.
이미 분석 중이던 항목은 그대로 끝납니다.

아이콘은 프로젝트 폴더의 `tray_icon.png`를 씁니다. 첫 실행 때 Windows용 `.ico`로
변환해 임시 폴더에 캐시하며, 창 제목 표시줄·작업 표시줄·알림 영역이 모두 같은
그림을 씁니다. 그림을 바꾸면 다음 실행에서 자동으로 다시 만듭니다.

### 검토창

`760×620`. 작은 창을 가리지 않도록 화면 왼쪽 위에 자리를 잡습니다.

- **왼쪽**: 원문. 기본은 수정 잠금이고 `원문 수정`을 눌러야 고칠 수 있습니다.
- **오른쪽**: 저장할 내용. 메시지별로 `메시지 1`, `메시지 2`처럼 구분됩니다.
- **오른쪽 위 `⋯`**: 기준일 설정 · 다시 분석 · 오프라인 규칙으로 분석 ·
  JSON 복사 · JSON 저장
- **아래**: `닫기`, `모두 등록 n건`

검토하는 동안에도 새 메시지를 계속 넣을 수 있습니다. **분석이 끝난 메시지는 기다리지
않고 같은 창에 이어 붙습니다.** 헤더에는 아직 분석 중인 건수만 `분석 중 n건`으로
표시합니다.

한 메시지의 카드를 모두 처리하면 초점과 왼쪽 원문이 자동으로 다음 메시지로 넘어가고,
메시지 헤더를 클릭하면 그 메시지의 원문으로 바꿉니다. 남은 카드와 분석이 모두 없어지면
창이 닫힙니다.

### 카드

한 카드가 Outlook 항목 하나입니다.

```text
┌──────────────────────────────────────────────┐
│ 제목 (길면 줄바꿈, 그 자리에서 편집)            │
│ [마감] 2026-09-21   시각 ____      등록 대기   │
│ 시청각실 · 조건부        [상세] [미등록]  [등록] │
└──────────────────────────────────────────────┘
```

- **제목**: 카드 폭을 다 쓰고, 길면 최대 4줄까지 늘어나 끝까지 보입니다. 바로 편집됩니다.
- **날짜/시각**: 상세를 열지 않아도 바로 고칩니다. 고치면 등록 가능 여부가 다시 계산됩니다.
- **`등록`**: 그 카드만 즉시 Outlook에 씁니다. 되돌리기 어려우므로 `미등록`과 떨어뜨려 두었습니다.
- **`미등록`**: 그 카드를 접어 둡니다. 다시 누르면 `되돌리기`로 대기 상태가 됩니다.
- **`상세`**: 분류(담임/업무/참조), 일시, 마감, 마감 시각, 종일, 장소, 알림, 반복,
  `마감일을 캘린더에도 표시`, 내역
- **아래 `모두 등록`**: 분석이 안전하다고 본 항목만 한 번에 등록합니다.
  조건부·확인 필요 항목은 포함하지 않으므로 카드에서 직접 눌러야 합니다.

카드 오른쪽 상태 라벨:

| 라벨 | 뜻 |
|---|---|
| `등록 대기` | 지금 등록할 수 있음 |
| `조건부 · 선택 시 등록` | 해당하는 사람만. 기본 선택 해제 |
| `확인 필요` | 수행 시각 등이 없어 등록 차단. 고치면 풀림 |
| `대상 확인 필요` | 나에게 해당하는지 불명확 |
| `중복 제외 · 사유` | 기존 항목과 겹침. 제목·시간을 고치면 풀림 |
| `등록 실패 · 사유` | Outlook 기록 실패. 고쳐서 다시 시도 |
| `등록 완료` | 끝남. 버튼이 잠김 |

참조·완료·중복 항목은 카드로 펼치지 않고 `참조/제외 n건 보기`에 접어 사유와 함께
보여줍니다.

## 메시지를 넣는 방법

### 1. 선택 텍스트 가져오기 (Ctrl+Shift+X)

다른 프로그램에서 텍스트를 선택하고 누르면 그대로 들어옵니다.

Windows에는 "다른 앱에서 지금 선택된 텍스트"를 읽는 API가 없어서, 다음 순서로 동작합니다.

1. 현재 클립보드 내용을 기억합니다.
2. 눌려 있는 Ctrl/Shift/X를 떼고 Ctrl+C를 합성해 보냅니다.
3. 클립보드가 바뀌면 그 텍스트를 가져옵니다.
4. 원래 클립보드 내용을 되돌려 놓습니다.

선택한 것이 없으면 현재 클립보드 내용을 대신 씁니다. 둘 다 없으면 작은 창에
안내가 나옵니다.

> 관리자 권한으로 실행된 프로그램에서는 Windows UIPI 정책 때문에 합성 Ctrl+C가
> 전달되지 않을 수 있습니다. 그때는 직접 Ctrl+C로 복사한 뒤 단축키를 누르면
> 클립보드 내용으로 처리됩니다.

### 2. 붙여넣기 (Ctrl+V)

작은 창을 클릭해 포커스를 준 뒤 Ctrl+V. `⋯ → 붙여넣기`도 같은 동작입니다.

### 3. 파일

작은 창에 드롭하거나, 창을 클릭해 파일 선택 창을 엽니다.

| 종류 | 형식 |
|---|---|
| 문서 | PDF, HWP, HWPX, DOCX |
| 텍스트 | TXT, Markdown, CSV, TSV, LOG |
| 이미지 | PNG, JPG, JPEG, BMP, GIF, WEBP, TIFF |

PDF/HWP 계열은 로컬에서 텍스트를 뽑아 분석합니다. 이미지는 `pytesseract`와
Windows Tesseract 실행 파일·한국어 언어팩이 설치된 경우에만 읽으며, 준비되지
않았으면 텍스트 붙여넣기를 안내합니다.

### 4. `key=value` 형식

직접 값을 지정하고 싶을 때 씁니다.

```text
title=학부모 상담
target=calendar
start=2026-09-10 14:00
duration_minutes=30
location=상담실
reminder_minutes=15
memo=상담 자료 준비
```

`target=both`를 쓰면 같은 입력에서 일정과 작업을 함께 검토할 수 있습니다.

## 분석

### 입력 예시

```text
2026-09-10 14:00 학부모 상담 장소: 상담실 알림 15분 전
2026-09-12 운동회 행사 장소: 운동장
2026-09-15 학생 명단 제출
```

시간이 있는 회의·상담은 Outlook 일정으로, 제출·확인·작성 등은 Outlook 작업으로
분류합니다. 날짜만 있는 Calendar 후보는 임의로 00:00/종일로 바꾸지 않고
`확인 필요`로 남깁니다.

모집·희망자·신청 공지는 날짜마다 나누지 않고 **실제 사용자 행동 단위**로 묶습니다.
예를 들어 `토익 시험 감독관 모집` + `시험일 2026-08-23 08:30` +
`당일 오전 10시까지 접수`는 `토익 시험 감독관 신청` Todo **1건**으로 남습니다.
신청은 조건부라 기본 선택이 해제되고, 시험일은 관련 행사 정보로, 날짜가 확정되지
않은 10시는 마감 시각 문맥으로 보존됩니다. 시험 참석 일정이나 `접수 마감 확인`
작업은 자동 생성하지 않습니다.

### 1차 분류 (scope) — LLM이 판단

| 분류 | 기준 | Outlook |
|---|---|---|
| 담임 | 최종 대상이 **학생**. 전달·안내·배부·지도 | 등록함 |
| 업무 | 최종 대상이 **나(교사)**. 제출·참석·이수·신청 | 등록함 |
| 참조 | 읽고 넘기면 되는 안내 | **등록 안 함** (SQLite에만 기록) |

### 2차 분류 (action) — 코드가 필드에서 파생

| 조건 | action | Outlook |
|---|---|---|
| 마감(`due`) 있음 | `todo_with_due_date` | 작업 + 마감일 + 내역 · 마감일에 캘린더 표시 |
| 일시(`at`) 있음 | `todo_with_date` | 캘린더 + 알림 |
| 둘 다 없음 | `todo` | 작업 (마감 없음) |
| scope=참조 | `none` | 등록 안 함 |

LLM에게 2차 라벨까지 물었을 때 실측 7%가 자기모순(`todo_with_due_date` 인데
`due=null`)이었습니다. 사실만 받아 코드에서 파생하면 그 모순이 구조적으로
불가능합니다. 검토창에서 분류나 일시/마감을 고치면 라벨이 즉시 다시 파생됩니다.

### 반복과 의미 필드

반복은 `repeat_freq`(daily/weekly/monthly) + `repeat_detail`("화,목")로 추출해
Outlook 반복 작업·일정으로 등록합니다.

추출 결과에는 실제 행동을 나타내는 `intent`, 조건부 여부인 `applicability`,
완료/안내 상태인 `source_state`, 그리고 `condition`, `due_time`,
`temporal_context`, `checklist`, `evidence`, `review_issues`가 함께 보존됩니다.
날짜가 여러 개여도 `event_context`·`external_deadline`·`historical` 같은 역할로
분리되어 주 행동의 등록 대상과 섞이지 않습니다.

### Solar Pro 4 호출 방식

API 키가 있으면 Upstage `solar-pro4`를 OpenAI 호환 endpoint
`https://api.upstage.ai/v1`로 호출합니다. 첫 요청 60초, 재시도 90초, 최대 2회.
모두 실패하면 오프라인 규칙 분석으로 넘어가고 검토창에 그 사실을 표시합니다.

추론은 `reasoning_effort="none"`이며, 간소화한 JSON Schema와 로컬 형식 검증을
함께 씁니다. 현재 프롬프트는 `semantic-v4-compact`로 API 필수 필드를 22개에서
12개로 줄였고, 빈 선택 필드·내부 ID·기본값은 앱에서 채웁니다.

분석은 백그라운드 FIFO 대기열에서 돌아가므로 새 메시지를 계속 넣을 수 있습니다.
오프라인 규칙으로 전환된 결과는 기본 선택이 해제되므로, 등록 전에 조건·확인 사유를
확인하세요.

### 기준일

`내일`·`다음주 월요일` 계산 기준입니다. 기본값은 오늘이며 검토창의
`⋯ → 기준일 설정`에서 바꿉니다. 메시지 발송일을 넣으면 정확해집니다.
본문에 발송일·작성일이 적혀 있으면 모델이 그것을 우선하도록 프롬프트에 규칙이
들어 있습니다.

### 등록 전 차단하는 것

잘못된 등록이 조용히 들어가지 않도록, 다음은 등록 전에 막습니다.

- 구조가 맞지 않는 JSON, 필수 필드 누락 응답
- **원문에 없는 수행 시각** (모델이 지어낸 `00:00` 같은 값)
- 시각이 정해지지 않은 Calendar 후보 (`start=null`)
- 조건이 없는 조건부 항목
- 대상이 불명확한(`applicability=unknown`) 항목
- Outlook 중복 조회 자체가 실패한 경우 → 등록 보류

## Outlook 등록

### 어디에 만들어지나

| 분석 결과 | Outlook |
|---|---|
| 일시가 있는 업무 | Calendar 약속 (+ 알림) |
| 마감일이 있는 업무 | 작업(Task) + 마감일, **그리고 마감일 당일 종일 표시** |
| 날짜가 없는 할 일 | 작업(Task) |
| 참조 | 만들지 않음. SQLite에만 기록 |

시간 일정의 종료가 없으면 저장할 때 60분을 씁니다. Todo는 `due=null`이어도
등록할 수 있고 `due_time`은 설명에 보존합니다.

### 마감일 캘린더 표시

Outlook 작업(Task)은 **캘린더에 나타나지 않습니다.** 그래서 마감이 있는 작업은
작업과 함께 마감일 당일에 종일 표시를 하나 더 만듭니다. 캘린더를 열었을 때 그날
무엇을 내야 하는지 보이게 하기 위해서입니다.

- 제목은 `[마감] 원래 제목`, 범주는 `마감`
- 하루를 차지하지만 **`한가함(Free)`으로 만들고 중복·시간 겹침 검사에서 제외**합니다.
  제외하지 않으면 마감일 하루가 통째로 막혀 그날의 실제 일정 등록이 모두 차단됩니다.
- 항목 하나가 Outlook 항목 둘이 됩니다(작업 + 표시). 필요 없으면 카드 `상세`에서
  `마감일을 캘린더에도 표시` 체크를 끄세요.
- 표시를 만들지 못해도 이미 만들어진 작업은 되돌리지 않고 사유만 알립니다.
- 같은 제목·같은 날짜의 표시가 이미 있으면 다시 만들지 않습니다.

일시가 있는 일정과 마감이 없는 할 일에는 만들지 않습니다.

### 중복과 시간 겹침

카드를 표시하기 전과 등록 직전, 두 번 확인합니다.

**Calendar**

- 기존 항목과 시간 구간이 겹치면 제외 (종료 시간이 없으면 60분으로 간주)
- 종일 일정은 하루 단위로 비교
- 같은 메시지에서 만든 일정끼리 겹쳐도 뒤의 것을 제외

**Todo**

- 제목의 공백·구두점을 정리한 뒤 비교
- 제목이 같고 마감일이 같으면 제외
- 마감일이 없는 동일 제목 Todo도 제외

제외된 카드는 사유를 보여주며, 제목이나 시간을 고치면 제외가 풀리고 다시 등록할
수 있습니다.

### Outlook 로컬 미러

카드마다 등록 버튼을 누르는 화면에서는 클릭할 때마다 Outlook 폴더 전체를 COM으로
훑을 수 없습니다. 항목마다 여러 속성을 COM으로 읽어야 해서 일정·작업이 많은
프로필에서는 클릭이 눈에 띄게 멈춥니다. 그래서 현재 프로필을 SQLite에 복제해 두고
중복 검사는 그 사본만 읽습니다.

| 시점 | 동작 |
|---|---|
| 앱 시작 | 전용 COM 스레드가 Calendar/작업 전체를 1회 읽어 미러를 채움 |
| 5분마다 | 같은 스레드가 다시 읽어 추가·변경·삭제를 반영 |
| 이 앱이 등록할 때 | Outlook에 만든 항목을 미러에도 즉시 기록 (write-through) |

미러가 오래됐으면 다음 중복 검사에서 백그라운드 갱신을 요청하되 결과를 기다리지는
않습니다. 첫 동기화가 끝나기 전에는 Outlook을 직접 읽습니다.

> **한계**: 다른 프로그램이 Outlook에 만든 항목은 다음 동기화 전까지 미러에 없습니다.
> 그 사이에 만들어진 일정과는 중복 검사가 되지 않으므로 최대 5분의 사각이 생깁니다.
> 클릭 반응성과 맞바꾼 값입니다. 동기화에 실패하면 작은 창 아래에 표시됩니다.

읽기 전용 동작이며 Outlook 항목을 바꾸지 않습니다. 미러는 로컬 SQLite에만 있고
외부로 보내지 않습니다.

### Outlook 연결 전제

`pywin32`로 `Outlook.Application` COM을 사용하므로 **클래식 Outlook**이 설치되어
있어야 합니다. New Outlook만 설치된 환경에서는 동작하지 않습니다. Outlook에
로그인한 상태로 실행하세요. `⋯ → Outlook 연결 확인`은 연결만 검사하며 새 항목을
만들지 않습니다.

Calendar/작업 읽기와 기록은 현재 PC의 Outlook 프로필에 대한 로컬 COM 자동화입니다.
Microsoft Graph 같은 외부 HTTP API를 쓰지 않으므로 학교 네트워크의 API 차단과
분리되어 있습니다. 같은 Microsoft 계정의 Outlook 작업은 Microsoft To Do와
동기화될 수 있습니다.

## 저장되는 데이터

### SQLite

DB 파일은 `data/work_items.sqlite3`입니다.

| 테이블 | 내용 |
|---|---|
| `inputs` | 원문, 생성 시간, 기준일·발송일·시간대 등 `context_json` |
| `work_items` | 분류, 제목, 시간/마감일, 장소/범주/알림, 설명, `saved`, Outlook `EntryID`, `calendar_entry_id`, 오류, `due_time`, 의미 필드 `semantic_json` |
| `outlook_mirror` | 현재 Outlook 프로필의 Calendar/작업 사본 (중복 검사용) |
| `sync_state` | 마지막 미러 동기화 시각 |

분석 직후 pending 상태로 먼저 기록하고, Outlook 기록에 성공하면 `saved=1`과
`outlook_entry_id`를, 실패하면 `last_error`를 남깁니다. 등록에 성공한 카드는
버튼이 잠겨 같은 항목을 두 번 등록하지 않습니다.

등록 상태는 다음과 같이 옮겨 갑니다.

```text
pending → saved
pending → failed
saved   → deleted   # 별도 관리 파이프라인에서 삭제된 경우
```

스키마가 바뀌면 앱 시작 시 자동으로 컬럼을 추가합니다. 기존 기록은 지우지 않습니다.

### 의미 정확도

회귀 fixture `test_set_30.xlsx`의 `테스트셋` 시트 본문 32건을 Solar Pro 4에
발송일과 함께 전달해 확인했습니다. 이 평가는 신규 메시지 전체의 일반화 점수가
아니라 프롬프트와 의미 필드의 기준선입니다.

> **아래 32건 수치는 프롬프트 간소화 이전 버전의 결과이며, 현재 버전의 정확도
> 점수가 아닙니다.** 축약 이후에는 속도만 재측정했고 의미 정확도는 재채점하지
> 않았습니다.

- 마지막 Solar Pro 4 32건: 31/32건 응답 확보, 1건은 2회 시간 초과 후 fallback
- 마지막 성공 응답시간: 평균 31.92초, 중앙값 27.62초, 95백분위 92.03초, 최대 97.53초
- 성공 응답 중 60초 이내 29건, 90초 이내 29건, 원문에 없는 `00:00` Calendar 0건
- 의미 기준 수동 감사: 완전 통과 12건, 부분 통과 11건, 개선 필요 9건

프롬프트 축소 후 합성 메시지 8회 실측은 평균 12.178초 → 4.606초입니다. 다만 빠른
완료 안내 2회를 뺀 실제 추출 6회 평균은 5.595초로, 목표 5초는 아직 미달입니다.
자세한 내용은 [LATENCY_REPORT.md](LATENCY_REPORT.md)를 보세요.

반복 실행 편차도 확인했습니다. 토익 모집은 3회 모두 `신청 Todo 1건`으로
안정적이었지만, 충전·책상 배열은 3회 중 2회만 2건 분리를 유지했고, 연수·감독의
조건부 처리와 긴 공지의 행동 단위 분리는 회차마다 변동했습니다.

**입력·플랫폼**

| 파일 | 역할 |

| `selection.py` | 선택 텍스트 캡처, 클립보드 읽기/쓰기/복원 |

**검증**

의존 방향은 단방향입니다: UI → service → 분류/저장/COM → models.
`models.py`를 고치면 거의 전부가 영향을 받고, `cards.py`/`review.py`를 고치면
UI 안에서 끝납니다.

### 단축키 바꾸기

`app.py`의 `VK_X`와 `HOTKEY_LABEL`, 그리고 `HotkeyListener(modifiers=...)`를
바꿉니다.

### 아이콘 바꾸기

`tray_icon.png`를 교체하면 됩니다. 배경이 투명하거나 반투명한 정사각형에 가까운
그림이 좋습니다. 앱이 알파값이 옅은 배경을 지우고 정사각형으로 잘라 여러 크기의
`.ico`를 만듭니다.

### 미러 동기화 주기

`outlook_mirror.py`의 `SYNC_INTERVAL_SECONDS`(기본 300초)와
`STALE_AFTER_SECONDS`를 바꿉니다.

## 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| 작은 창에 단축키 등록 실패가 뜬다 | 다른 프로그램이 Ctrl+Shift+X를 쓰고 있습니다. 그 프로그램을 끄거나 `app.py`에서 조합을 바꾸세요. 그동안에도 `⋯` 메뉴의 붙여넣기·파일 선택은 됩니다 |
| Ctrl+Shift+X를 눌러도 아무것도 안 들어온다 | 상대 프로그램이 관리자 권한입니다. 직접 Ctrl+C로 복사한 뒤 다시 누르세요 |
| `Outlook 동기화 실패`가 뜬다 | 클래식 Outlook이 실행·로그인 상태인지 확인하세요. 실패해도 첫 등록 시 Outlook을 직접 읽습니다 |
| 등록이 `중복 확인 실패로 보류`된다 | Outlook을 읽지 못했습니다. 중복 검사는 안전 전제라 건너뛰지 않습니다. Outlook 연결을 확인하세요 |
| 이미지에서 글자를 못 읽는다 | Tesseract 실행 파일과 한국어 언어팩이 필요합니다. 없으면 텍스트를 붙여넣으세요 |
| 트레이 아이콘이 없다 | 작은 창이 제목 표시줄을 유지하므로 `X`로 종료할 수 있고, `⋯` 메뉴에도 일시중지·종료가 있습니다 |
| 작은 창을 옮기고 싶다 | 위쪽 `업무 정리` 줄을 잡고 끄세요. 제목 표시줄이 없어 그 줄이 손잡이입니다 |
| 마감일마다 캘린더가 막힌다 | 마감 표시는 `한가함`이고 겹침 검사에서 빠지므로 이 증상은 없어야 합니다. 다른 프로그램이 만든 종일 일정인지 확인하세요 |
| 작업 표시줄에 파이썬 아이콘이 보인다 | `python app.py`로 실행했는지 확인하세요. `main()`에서 앱 식별자를 설정합니다 |

## 개인정보

- 원문은 SQLite `inputs.original_text`에 **그대로** 저장됩니다.
- 현재 요구사항에 따라 **PII 탐지·마스킹은 수행하지 않습니다.**
- API 키가 있으면 원문이 Upstage API로 전송됩니다. 키가 없으면 외부로 나가지 않습니다.
- 로컬 `.env`, `profile.json`, `data/*.sqlite3`, `test_set_30.xlsx`는
  `.gitignore`로 제외되어 있습니다. 이 파일들을 공유하지 마세요.
